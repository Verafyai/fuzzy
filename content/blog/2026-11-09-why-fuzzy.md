For most of Solana's history, the person deciding whether to trust a program was a person. They read the docs, asked in a Discord, looked for an audit, and decided. Security tooling grew up around that person. Audit firms write PDFs. Open-source fuzzers like Trident give a developer a framework to write attacks by hand. Newer AI reviewers read code and list the bugs they think might be there.

That world is changing fast. Agents now hold wallets, call programs, and move money without a person reading anything first. An agent that wants to swap, lend or pay through a program it has never seen has nothing it can check. A website can say anything. An audit PDF describes some build, maybe not the one deployed today, and an agent cannot read it in any meaningful way anyway.

Two things are missing. The first is proof. Scanners produce long lists of possible issues, most of them false alarms, and developers learn to ignore them. The second is a record an agent can check: tied to the exact code that is deployed, written by someone who can't simply vouch for themselves, and readable in one call.

## What changed

Three pieces exist now that didn't a couple of years ago.

**Exact local execution.** LiteSVM runs real Solana transactions in-process against real program bytecode, and mainnet accounts can be cloned into it. Every guess about a bug can be tested for certain, cheaply, without touching the network.

**Juries of models.** Verafy Harness seats juries of AI models from different model families, has them commit to their votes before anyone reveals, and seals the ruling on Solana. A jury can read evidence and rule on it, and its ruling is a public, checkable object.

**Agents that need it.** The buyers of this are increasingly software. They don't need a PDF. They need an account they can read.

## What Fuzzy does

You drop a compiled program into fuzzy.verafy.ai, or paste a program address. Fuzzy learns how the program works from its IDL, or by replaying its recent mainnet calls against cloned accounts, and then it attacks every path it found. It drops required signatures, re-runs setup as a stranger, swaps in look-alike accounts owned by another program, and pushes arguments to their limits.

A finding counts only if the attack transaction actually succeeds and moves funds to the attacker or writes the attacker in as an authority. Everything else is a lead: shown, never scored. Every finding comes with the transaction that proves it. On our benchmark vault, a program we wrote with two deliberate bugs, Fuzzy found both, chained one of them into a full drain, and scored it 20 out of 100. The fixed build of the same program came back with no findings.

Each run produces a Fuzzy Score: the lower of how deeply Fuzzy tested the program and a ceiling set by the worst proven bug. A shallow run can't score high because it found nothing, and a deep run can't score high while a critical bug exists.

## The report card goes on chain

The part I'm most excited about is the Verafy Certification. A Fuzzy report goes to a Verafy jury of registered harnesses, and the jury rules which level the program earned: Sniffed, Fuzzed or Hardened, or not certified at all. A small Solana program writes that level to an account derived from the program address and the hash of its exact bytecode. It refuses to write unless a sealed jury ruling backs it, with at least three registered harnesses from at least two model families. Nobody can certify their own program by signing a transaction.

For an agent, checking a program is one read: hash the program's current bytecode, read one account. If the program is upgraded, the hash changes and the old certification no longer applies, so a certification never vouches for code it didn't test. The first certification is live on devnet today, for the fixed build of our benchmark vault.

## The rules can't be quietly loosened

A certification is only worth something if its rules hold. Fuzzy's rules live in a charter with protected articles: only proven findings count, a certification names one exact build, only a jury certifies, and nothing already issued ever changes. Anyone can propose an amendment. A Verafy jury adopts it only if every protected article still holds, and when the jury is unsure, the answer is no.

## What it is not

A high score means the program survived these attacks. It is not an audit and not a promise of safety. Branch coverage isn't measured yet, so no score from this version goes above 55, and token balances aren't part of the proof yet. Deeper tiers with cloned mainnet state and model-planned attacks come next.
